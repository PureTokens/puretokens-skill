# Video rules

当前只支持文生视频，不支持参考图片/视频、上传素材、去物体、重绘或其他编辑输入。遇到编辑请求，说明可用文字描述生成新视频，不得访问用户媒体或假装编辑成功。

## 视频模型与通道

先保留用户在宿主 UI 或工具上下文主动选择的、能证明精确 `video` 模型和真实视频交付的 Pure Tokens 原生执行器；普通聊天模型配置、模型文字或组件不是执行器。

默认视频模型是 `grok-imagine-video-1.5-preview`。除已选原生执行器外，模型必须由认证后的 `GET https://api.puretokensx.com/v1/media/models` 返回的精确 `id` 与 `video` 能力确认。别名只能产生候选；歧义时列出精确 ID 并请用户选择。README 清单只用于发现，不能证明当前连接可用。

在 Codex 或 CC Switch 中，只有宿主明确把当前 Pure Tokens 连接提供为可调用、已认证的 HTTPS 视频执行器，并能下载和交付真实视频字节时，才能：读取同一连接的实时目录 → 确认精确 `video` 模型 → 单次 `POST https://api.puretokensx.com/v1/videos` → 只轮询返回的同一 `task_id` → 从同一任务 `/content` 取得真实字节。仅保存 API Key 或能读取目录不是视频执行能力。

其他宿主依次使用：已选原生执行器；可调用的 `puretokens-image` MCP（先 `puretokens_list_media_models`，再以精确 `model` 和稳定 `request_id` 一次 `puretokens_generate_video`，之后仅以 `puretokens_video_result` 查询同一任务）；或已由宿主 Secret/环境机制注入 Pure Tokens 凭据、具备 HTTPS 和真实本机交付能力的 Direct Cloud。

若 CC Switch/Codex 当前连接不能直连指定模型，任何备用提交前必须说明不能直连的精确模型、已验证的同模型备用通道，并明确不会换模型；没有同模型通道则停止。Connection Videos API 的目录、提交、轮询或交付失败时停止；不要改走 MCP、Direct Cloud 或其他模型。

## 参数、任务与交付

仅传递用户明确给出的时长、画幅、分辨率或尺寸；当前精确模型或端点拒绝时，原样说明并请用户改为实际可选项或省略。不得用相近参数或另一模型替代。

视频总是异步任务。只有同一任务取得实际视频字节并由执行层完成真实交付时，才能说成功。任务 ID、文字、SVG/HTML、组件、上游 URL 或假造本地链接不是视频。轮询超时或仍在处理中时说明尚未交付，并让用户稍后请求继续查询同一任务；不能新建任务。

## 面向用户的特殊情况

- 模型名称、别名或供应商匹配到多个候选时，列出当前认证目录中的精确视频模型 ID 和已返回的显示信息，请用户选择；目录为空、模型不存在或没有 `video` 能力时，说明当前连接没有可用的视频模型。不得猜测或改用相近模型。
- MCP 不可用时，只能在宿主已经具备 HTTPS、已注入 Pure Tokens 凭据和真实本机交付能力的情况下使用 Direct Cloud；否则明确说明缺少可调用的视频执行通道。只有确认是 Desktop 受管 MCP 时，才引导用户选择包含该模型的分组、点击“验证并应用”、重启客户端并新建会话；自管连接只应检查自己的凭据和模型范围。
- 提交、轮询或内容交付报错（包括 `safeToResubmit=false`）时，如实说明当前任务失败或状态未知；不得自动换模型或重新提交。轮询超时或仍在处理中时，引导用户稍后继续查询同一 `task_id`，而不是新建任务。
