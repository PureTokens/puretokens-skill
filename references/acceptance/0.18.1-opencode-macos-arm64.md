evidence only. It is not authenticated API or media acceptance.

## Selection diagnosis

On 2026-09-12, an explicitly authorized native recheck against the unchanged
installed executor exited 1 in 20 ms. Its sanitized receipt again reported
`active_connection_selection_unconfirmed`, with `api_request_executed`,
`api_identity_confirmed` and `credential_verified` all false. This command
was not invoked by an OpenCode conversation and does not establish any
additional real-host acceptance case.

The matching OpenCode 1.18.23 upstream tag resolves to commit
`ef2880f379129aa048be9e9353e30aa168d42c17`. Static inspection identified a
selection-scope mismatch:

- Our `runtime/executor/credentials.go`, `credentialFromOpenCodeFile`, reads
  only the declared global JSON record and requires its `model` to contain
  a provider selection before examining an endpoint.
- Upstream `packages/opencode/src/provider/provider.ts`, `defaultModel`,
  treats the configured model as optional, then considers valid recent
  models and an available configured provider/model.
- Upstream `packages/opencode/src/session/prompt.ts`, `createUserMessage`
  and `currentModel`, also consider explicit request, agent and session
  selections. The last-used model file is therefore not proof of every
  running session's choice.
- Upstream `packages/opencode/src/config/config.ts` merges global JSON and
  JSONC plus declared project/override sources. Reading one global file
  does not reproduce this effective configuration.
- The reviewed upstream `packages/opencode/src/tool/shell.ts` and
  `packages/core/src/tool/bash.ts` execution paths do not establish a fixed
  current-provider/model environment contract usable by this adapter.
  Plugin-provided environment values must not be guessed or assumed.

An isolated Go test overlay reproduced the selection boundary using six
synthetic cases: omitted/null/empty/unqualified defaults stop locally; a
fully specified synthetic default resolves; an explicitly selected unrelated
endpoint does not borrow another configured entry. All six observations
matched the existing executor behavior. The first probe contained malformed
synthetic JSON; it was corrected to use structured JSON encoding before
recording these outcomes. No product code was changed to make the probe pass.

These results identify the rejecting adapter branch and a supported-scope
gap, not the actual source of this user's current session selection. No
private configuration, recent-model file, session history or authentication
store was inspected. A fix must establish the effective same-host selection
or explicitly define a narrower verified service-connection capability;
deleting the guard, taking the first provider, or copying a model name into
the user's configuration would not establish that proof.

The source snapshots and synthetic probes are under
`/tmp/pt-opencode-diagnosis.6vBdzU`. The authenticated and media acceptance
cases remain pending; no paid task was submitted.
